# StateTTT / LongLive 2.0 distillation: L20 step200 and H100 step300

The H100 single-GPU5 recipe and complete launch/recovery instructions are in
tools/distillation/H100_README.txt. It pins step300, uses effective batch2 via
two sequential full-episode microbatches, and requires single-rank CUDA tests
and independent 25/61/121-latent capacity acceptance before its formal500/2500
updates. The teacher step/hash, GPU mapping, world size, actual byte budget,
accumulation and code identity are configuration-bound, not L20 constants.
Capacity and formal outputs are separate; initial capacity updates are discarded.
The existing step200 two-GPU L20 configuration remains available below.

This backend keeps the H100 step-200 TLA and StateTTT state equations. LongLive
2.0 supplies the alternating DMD objective and score-distillation schedule;
`sampler.py` is the TTN-specific causal, differentiable rollout. Teacher,
student and fake-score models own separate state and camera caches. The teacher
is frozen; student and fake-score train independent rank-128 LoRA adapters and
the ten StateTTT basis/gain tensors. The first observed latent is fixed and
excluded from both losses. The student graph spans the whole episode, with no
TBPTT or detached generated history in its update path.

On L20, `python tools/distillation/launch_l20.py` starts a unique `wm` tmux
window on physical GPUs 6 and 7. It first runs actual 25/61/121-latent
student and fake-score backward/optimizer acceptance. Only a passing capacity
receipt allows the formal 500-student/2500-fake update run to start. The formal
startup also compares the next update on both ranks before and after a saved
recovery bundle. The enclosing cgroup caps total RAM at 360GiB and disables
swap; PyTorch is capped near 40GiB per card. Saved activations use uncompressed
pageable CPU storage. All failures leave a terminal status and log, and never
advance to the next phase silently.

All three roles use native FSDP2 pageable CPU parameter offload; student and
fake-score optimizer states also reside on CPU. Clipping reduces a CUDA scalar
under NCCL, and adapter export stages one tensor at a time for the CUDA gather.
Fake-score noisy prediction and clean writes use separate
checkpoints, so rebuilding clean history does not also replay an unused noisy
prediction. Both retain the original history gradients. Replayed FSDP2 modules explicitly call the public
`unshard()` API before their normal forward hooks: recurrent reuse can revisit
a resharded module while FSDP2 still marks it as pre-backward. No internal FSDP
state, parameter dtype, state equation or gradient is changed.

Camera Q/K/V projections preserve their original fused fast path for plain
Linear modules. Adapter wrappers run their own forwards so the base-weight
fusion cannot bypass LoRA. Capacity acceptance rejects missing camera LoRA
gradients as well as missing StateTTT gradients.

GDN beta, decay and output gate methods also preserve adapter forwards rather
than reading only base weights in their compiled helpers. Plain Linear paths
are unchanged. Acceptance now rejects every missing selected LoRA gradient,
including these 90 tensors across the15 GDN blocks. The frozen full-DiT
teacher is unaffected; this correction applies to the distillation adapters.

After the eight-step run completes, generate fixed 30/60-second teacher-20,
undistilled-8, best-student-8 and student-8 TTT-off videos on the same held-out
case and per-duration noise. Run this in a separate two-rank GPU 6/7 allocation
after formal training has released those cards:

```bash
CUDA_VISIBLE_DEVICES=6,7 python -m torch.distributed.run --standalone --nproc_per_node=2 \
  -m tools.distillation.review_videos --run /path/to/completed-eight-step-run
```

MP4s and a manifest are written to `<run>/review-videos/`; this is a
qualitative comparison, not a teacher-unseen claim. Review both durations
before recording the result. A
review file containing `{"source_sha256":"<best-adapters.pt SHA256>",
"video_review":true}` permits
`python tools/distillation/prepare_stage4.py --eight-run <run> --review-file <file>`
to prepare a four-step config only if per-case LPIPS and late MSE are within 5%
of teacher-20 and measured FPS is higher. It does not launch stage four.
`python tools/distillation/launch_l20.py --config <prepared-stage4.yaml>`
then starts a separate guarded run, transferring student EMA and fake-score
adapters while resetting both optimizers, EMA and update counts. Video review
must reflect real visual inspection; the numerical gate alone is insufficient.

Current L20 validation is recorded in the run logs. CPU unit tests establish
the sigma/CFG math, DMD direction/mask, LoRA initialization, temporal gradient,
recomputation and single-rank exact restore. A separate two-rank capacity and
resume acceptance is required before any claim about full-length training.
